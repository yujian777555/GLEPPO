## 2. GLEET findings (condensed)

- **What GLEET is:** PPO configures the exploration–exploitation split (c1/c2) of PSO/DMSPSO/DE on shifted/rotated CEC 2021 functions. Dense reward = relative gBest improvement normalized by initial best. Transformer-set policy over a 9-feature per-individual state.
- **What GLEET is not:** it does not evolve agents, does not use task-execution feedback, does not choose variation operators or parents, and does not handle sparse/noisy real-world evaluation.
- **Paper vs code (material):** network width/depth (128-d × 2 layers vs 16-d × 1 layer), train:test instance sizes (128:1024 vs code defaults 1024:128), c1+c2 sum (paper 4 vs code ≈2.99 / 4.1). Anyone citing or reproducing GLEET numbers must resolve these.
- **License:** **no open-source license** on the official code. GLEPPO must implement independently and cite as a paper. Code copying is forbidden.

## 4. Candidate mechanisms (condensed; full spec in `research/CANDIDATE_MECHANISMS.md`)

**Shared protocol:** minimal LLM-agent genotype with causally effective edits; real execution episodes; train families → validation → **frozen** controller on held-out family C; baselines B0–B5 including **bandit (B3)** and **LLM-as-operator (B5)**; leakage hygiene; multi-seed.

### M1 — Execution-Conditioned Operator Selection (ECOS)
- State: execution outcome features (success, failure-type histogram, cost) + population/operator-history/progress.
- Action: discrete choice among K restricted variation operators (one decision family only).
- Reward: offspring-vs-parent success delta on training-task eval subset + validity.
- **GO:** beats bandit and adaptive rule on held-out family (95% CI), ablation without execution features loses, ≥ competitive with FM-rewrite at equal budget.
- **NO-GO:** bandit matches PPO; or fitness-only state ≈ full state; or no transfer.

### M2 — Failure-Mode-Conditioned Parent Selection (FMPS)
- State: per-agent failure-mode profile + pairwise compatibility + population context.
- Action: parent-pair selection from shortlist (operator held fixed).
- Reward: crossover-offspring success vs better parent + validity.
- **GO / NO-GO:** same pattern as M1, with failure-feature ablation as the key probe.

**Cross-rule:** if neither GO → **STOP** the PPO-evolution-controller hypothesis as scoped; do not add a third decision family to rescue it.

## 5. Gate decision

# **GO**

**To:** Phase 1 — define the agent-evolution problem (genotype, environment, evaluator, task-family split) and freeze the primary decision family (M1 or M2, not both in v1).

**Basis for GO:**

1. **Baseline audit complete and traceable.** GLEET's algorithm, code, and license are recorded with paper-vs-code discrepancies; the license finding (no reuse) is binding and unblocks independent implementation.
2. **A testable mechanism-level gap exists.** The verified literature occupies "RL controls numeric EC", "NN-learned operators for black-box optimization", and "LLM evolves agents/programs with evaluators" — but not the conjunction of a PPO policy, execution-feedback state, agent-evolution decisions, and held-out task-family transfer. The gap is honest about its bounds and is paired with experiments that can kill it.
3. **Two candidates are specified tightly enough to falsify.** Each has state/action/reward/split/baselines and an explicit NO-GO rule that does not allow rescue-by-complexity.
4. **Charter constraints are respected.** Real execution grounding; no budget-allocation novelty; no "PPO on agent evolution" claim; GLEET code not reused; no fabricated results.

**Conditions attached to GO (violating any of them converts to REVISE/STOP):**

| # | Condition | Enforced at |
|---|---|---|
| C1 | Do not copy or transliterate GLEET code. Implement independently. | All phases |
| C2 | Pick **one** decision family (M1 *or* M2) before implementation; do not combine. | Phase 1 |
| C3 | Bandit (B3) and FM-rewrite (B5) baselines are mandatory in any effectiveness experiment. | Phase 2–3 |
| C4 | Re-run a deeper literature collision check (Google Scholar / Semantic Scholar; open DRL-PSO, RLEPSO, HELIOS) before interpreting Phase 3 as a novelty claim. | End of Phase 2 / pre-submission |
| C5 | If PPO does not beat B3 on held-out families (M1/M2 NO-GO rules), **STOP** this hypothesis — do not enlarge action spaces or stack modules. | Phase 4 |

**Why not REVISE:** the plan does not need redesign; the remaining unknowns (genotype choice, task families) are Phase 1 deliverables, not defects in the audit.

**Why not STOP:** a falsifiable gap and at least one non-trivial experiment design exist. Stopping now would be premature; stopping after a failed bandit comparison is exactly what C5 is for.
